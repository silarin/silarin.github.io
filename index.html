02 / Engineering boundaries

Authority is part
of the design.

Research code should not quietly become trading code. Market-data observations should not quietly become account truth. The repositories encode those distinctions directly.

From source to decision

A narrow, inspectable path keeps provenance and execution authority visible.

01 Acquire explicit inputsOfficial public archives or tightly scoped OKX endpoints.
02 Validate before useIdentity, sequence, schema, checksum, precision, and configured authority.
03 Fail closed on ambiguityNo synthetic replacement for missing evidence or unknown exchange state.

Shared engineering principles

The projects vary in capability, but their correctness posture stays consistent.

// Exact economic valuesPrices, quantities, fees, notionals, and book levels remain decimal at critical boundaries.
// Deterministic evidenceChronological replay, explicit inputs, checksums, and create-new outputs make research auditable.
// Narrow operational authorityCredentials, private state, and order capability appear only where the runtime explicitly requires them.
// Exchange truth winsAmbiguous mutations and private-stream hints are reconciled against bounded REST authority.
